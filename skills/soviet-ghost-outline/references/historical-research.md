# 历史研究与暂停规则

不要把未经核实的真实历史主张写成 Canon 或剧情事实；也不要因为题材常出现历史名词而频繁中断创作。

## 三类问题

| category | 含义 | 示例 | 处理 |
| --- | --- | --- | --- |
| `historical_fact` | 可核实、剧情直接依赖的真实事实 | 某年某项安全事务由哪个真实机构负责 | 尚未确认且会实质改变剧情时必须研究并暂停 |
| `historical_plausibility` | 基于真实制度逻辑的可行性推演，不是已证事实 | 若虚构亡灵管理局存在，真实机构可能如何监督 | 可研究并由用户拍板；明确标成推演，不得伪装成史实 |
| `fictional_institution_design` | 完全架空的机构规则 | 死亡证明需要几联、窗口如何编号 | 不触发历史暂停；检查其是否违反已确认 Canon 或明显背离整体制度逻辑 |

## STOP 条件

只有当**当前剧情决策实质依赖一个尚未解决的真实历史事实**时，才建立强制暂停。不能仅因提到苏联、KGB、德国、军衔、制服、国籍、语言或行政机关就停止。

如果相关历史事实已经在项目级 Canon 或已确认的历史 baseline 中，不要在每集重复触发研究。若剧情只需要合理推演或纯架空规则，应在记录中标清类别和不确定性，不得将推演升级成事实。

## 记录结构

```json
{
  "id": "HR-001",
  "category": "historical_fact",
  "claim": "故事依赖的具体历史主张",
  "status": "RESEARCH_REQUIRED",
  "storyImpact": "该事实将改变哪项剧情决策"
}
```

状态为 `CANON`、`PROVISIONAL` 或 `RESEARCH_REQUIRED`。条目需含 `id`、`category`、`claim`、`storyImpact`。只有仍处于 `RESEARCH_REQUIRED`、属于真实历史依赖且会实质改变剧情的条目阻止 `--stage full`。`fictional_institution_design` 本身不造成暂停。

## 暂停时的处理

仅对触发条件成立的问题暂停，并列出可供用户选择的路径：

```text
## 历史研究暂停点 HR-001
涉及的故事决策：
历史问题类别：
待确认的事实：
对故事的影响：
选项：开展研究 / 用户提供设定 / 明确架空 / 删除相关依赖
[STOP — HISTORICAL CONFIRMATION REQUIRED]
```

不得根据模型记忆补齐真实事实。用户明确选择架空后，将内容记录为虚构设计，而不是历史事实。
